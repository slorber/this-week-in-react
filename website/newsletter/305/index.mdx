## ⚛️ React {#react}

![Rebuilding the global town square from scratch](/emails/issues/305/x-town-square.jpg)

[**X Engineering \- Rebuilding the global town square from scratch**](https://blog.x.com/en/engineering/rebuilding-the-global-town-square-from-scratch)

One of the world's largest React apps is currently rolling out a major rewrite. Logged-out users and crawlers already see the new app, and signed-in users are moving over one country at a time. Since Twitter Lite (2017), X has been a client-side React app: the browser downloads JavaScript, then asks for data, then renders, leading to performance issues. Additional SSR servers handled search crawlers and link-preview bots. The new architecture uses a single server for people, crawlers and link-preview bots, and optimizes its response according to who's asking.

The article is a detailed write-up sharing various lessons learned and impressive performance results, in particular on slow connections, where a profile's first post now shows in 2.7s instead of 23.9s. Since we are a React newsletter, here's what is likely to interest you the most:

- **New stack** \- The new app is built on Vite, React, Relay and Fastify. The former stack already used Relay/GraphQL, which remains interesting for colocating data requirements with components and making preloading easy.
- **Streaming SSR with Suspense** \- The server sends the page shell right away, then streams each part as its data arrives. Profiles and posts download no JavaScript before the first post shows.
- **Hydrating before the stream ends** \- With an async module entry, React hydrates the shell immediately, then each boundary as it streams in. They also prioritize the loading of the render-blocking stylesheet: even if it slightly delays React hydration, it gives a better First Contentful Paint on slow connections.
- **Relay without refetching** \- Route loaders start the GraphQL queries while the server renders. The page carries each response once as JSON, and the browser replays it into an empty Relay store.
- **Intent preloading** \- Links preload their route's code and data on hover or focus so that navigation feels fast.
- **AI usage** \- Five engineers built the first version in under six months. Agents helped with the implementation, porting behaviors of the old servers to the new architecture, with scripts to ensure parity.

Any `setTimeout` created during SSR captures the `AsyncLocalStorage` contexts. Here, the React Query GC timer led to that leak, capturing the Next.js Request store. ## 📱 React-Native {#react-native}

![A preview of Exact](/emails/issues/305/exact.jpg)

[**Exact \- Agent-native app framework in Rust**](https://ccheever.expo.app/)

Expo co-founder Charlie Cheever shared a pre-alpha preview of Exact. It's a cross-platform app framework written in Rust, designed for agents to write, run and test apps. You describe the UI in 𝕏 [Contract](https://x.com/JI/status/2119779463827431853), a new declarative language, and write the logic in TypeScript or Rust. Models have never seen Contract, but it's small and constrained on purpose, so agents learn it quickly. Exact promises near-instant startup, smooth scrolling, edits applied in about 100ms, and the same test running unchanged on web, mobile and desktop.

🧵 [**Discord follows Shopify, leaving React Native for native and Rust**](https://x.com/svishnevskiy/status/2118081920194203799)

Another big app is moving away from React Native\! Discord is dropping both Electron and React Native, extending its shared Rust core. On desktop, the UI moves to GPUI. On mobile, the Rust core now drives native views.

It comes only two months after Shopify left React Native, but the approach is quite different. Shopify went back to separate Swift and Kotlin apps, betting that agents make writing the code twice affordable. This week, they explained [how they rebuilt the app in 12 weeks](https://shopify.engineering/shopify-app-rebuild) with Helix, Reflex and remote dev. With [Reflex](https://shopify.engineering/reflex), a single behavior test suite runs against headless ViewModels, without a simulator, to keep iOS and Android in sync.

Related resources:
