- 👀 [React Concurrent Store PR \- Ricky Hanlon runs React's own state tests against the unofficial ponyfill](https://github.com/thejustinwalsh/react-concurrent-store/pull/27)
- 👀 [Next.js PR \- `router.experimental_prepare()` to start a navigation on pointerdown and commit it on click](https://github.com/vercel/next.js/pull/101050) \- This is quite an exciting feature I’ve been wanting for years. There’s a delay between pointerdown and click events. Now you can “prepare” a navigation ahead of time, even if the user hasn’t really clicked your link yet. Once the click is confirmed, you commit the pre-warmed navigation that should feel faster. This may be integrated into the `<Link>` component eventually.
- 👀 [Next.js PR \- `create-next-app` always uses the App Router, no router choice prompt](https://github.com/vercel/next.js/pull/100850)
- 👀 [Next.js PR \- Experimental Go Route Handlers with `route.go` files](https://github.com/vercel/next.js/pull/100130) \- The Next.js team is prototyping native language support for CPU-intensive server work next to your React app, starting with Route Handlers and Proxy in Go.
- 📜 [React.lazy, Suspense and the Hidden 300 ms Delay](https://tabwidgets.com/blog/react-lazy-suspense-delay) \- A `React.lazy` component always suspends on its first render, and React throttles Suspense reveals to 300ms to avoid flicker, which can be a problem in some cases.
- 📜 [Async React & Progressive Server Actions](https://ebey.dev/blog/3myyseusgd22h) \- When using Server Actions with client-side optimistic UI, it’s easy to break your form progressive enhancement behavior. Thankfully, you can restore it with a simple trick: only wire the optimistic action after hydration.
- 📜 [Understanding React internals](https://www.alexandretrotel.org/articles/understanding-react-internals) \- A 6-chapter tour, from Fizz and Flight on the server to hydration, lanes and the commit phase, with code taken from React's source.
- 📜 [Writable Derived State: Stop Synchronizing State](https://playfulprogramming.com/posts/writable-derived-state/) \- Instead of syncing server data into local client data with `useEffect`, you could simply use `clientData ?? serverData`. The client data can be null after a server refresh.
- 💸 [PropelAuth - How to Build a Good Consent Screen for OAuth And MCP](https://www.propelauth.com/post/good-consent-screen-for-oauth-and-mcp?utm_source=twir&utm_campaign=nov4&utm_medium=newsletter)

- 📦 [React Resizable Panels 4.16 → 4.18 \- New `<Workspace>` component for IDE-like layouts, draggable and collapsible tabsets](https://github.com/bvaughn/react-resizable-panels/releases)

## 📱 React-Native {#react-native}

![Vega OS 2.0](/emails/issues/304/vega-os-2.jpg)

[**Vega OS 2.0**](https://developer.amazon.com/apps-and-games/blogs/2026/10/vega-2-0-sdk-launch)

Vega OS 2.0 is out now on every Vega-powered Fire TV, [bringing RN 0.83: React 19, the compiler, Hermes v1, and real DevTools](https://developer.amazon.com/apps-and-games/blogs/2026/10/react-native-for-vega-os).

It also brings native APIs, agent-assisted migrations, and stable minors with one major a year.

- **TV focus states** \- new boxShadow and outline props, plus compat updates for Navigation, Reanimated, and Lottie.
- **Beyond RN** \- native APIs for task scheduling and custom UI, with hybrid-UI and periodic-task sample apps.
- **DevAssistant** \- docs AI with a Vega domain selector and page-level context, so less doc-hunting.
